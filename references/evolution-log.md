### 一、`docxlib.replace_in_texts()` 有一个之前没记录的失效模式：old 跨多个 w:t 时清空节点

SKILL.md 陷阱十只记了「会留下空 w:t 节点」。本次实测**更严重**：当 `old` 同时命中
**多个 w:t 节点**时，`spans` 用的是**已被修改后的**节点文本，于是

* 命中区间内的**第一个**节点被写成「整段新文本」；
* 区间内**其余节点被整体清空**（不是只删被匹配的片段，与函数 docstring 的说法不符）。

最小复现（`_task/学生J/bug_repro.py`）：段落 = 正文 run「前面一句话。」+ 上标 run「[1]」+ 正文 run「后面一句话。」，
`replace_in_texts(p, '前面一句话。[1]后面一句话。', '前面一句话。[1]后面加了新内容。')` 返回 1，
结果三段文本被压成**一个普通 run**：

```
r0 '前面一句话。[1]后面加了新内容。'   ← [1] 的上标格式丢了、且嵌进了正文 run
r1 ''
r2 ''
```

本次由此连踩两坑：段 74/75 的 `[4]`/`[5]` 角标被清空（产物里只剩空上标 run），
段 79 的 `[6]` 被搬到句号之后。**处置（三条铁律）**：

1. 调用前先断言 `flat(p).count(old) == 1`（`old` 在段内**唯一**）——循环不会走第二遍，
   就不会读到被污染的 spans；
2. 替换后断言 `flat(p) == before.replace(old, new, 1)`，不等就立刻退出；
3. **不要**用「整段文本 → 整段文本」的替换来做引号规范化或占位符转编号——
   逐 `w:t` 节点改 `t.text` 才是安全的（本次改成逐节点处理后一次通过）。

### 二、需要给"上标占位符"编号时，`add_text_runs()` 只认数字，不认 key

`docxlib.SUP_RE = Q([0-9]+)Q`，因此用「文献 key」做占位符（`§li2023§`）时
`add_text_runs()` 完全不转换，占位符原样落进正文。正确姿势：

* 编号必须在**改文本之前**由"引用点文档顺序"推导（本次把 EDITS 的新文本与 REWRITE 的文本
  按段号一起扫描，等价于改完后的顺序）；
* 自建 `build_runs()`：按占位符把文本交替写成 `正文 run + 角标 run`，**不要**借道 `set_text`；
* 对已在段落里的占位符：拆 `w:t` 所在的那个 **run**（不是 `w:t`！），把角标 run 作为
  **段落直属子元素**插在前后两条 run 之间。写成 `t.addnext(sup)` 会得到
  `<w:r><w:t/>...<w:r>角标</w:r></w:r>` 的非法嵌套（本次踩中，20 处）。

### 三、跨多 run 的 REF 交叉引用域：整组搬，不要"删了再补"

段 104 的 `[6]` 不是一个 run，而是**跨 7 个 run 的域**：
`'[' + fldChar(begin) + instrText(REF _Ref103676123) + fldChar(separate) + '6' + fldChar(end) + ']'`，
且 `'。'` 在域之后的 run 里。原来"删掉这几个 run、再 `append_run` 补一个 `[6]`"的写法，
补出来的角标只能落在**段末**（越过句号），`check_citation_placement()` 立刻报
"角标落在标点之后"。正确做法：把整组 run **原样 `addprevious` 到 `'。'` 之前的 run 前**，
域结构不动、位置正确，还能继续交叉引用。

**顺带解释一个"看走眼"**：`check_citation_placement()` 对这类域的 `prev_ch` 判定是
**取最后一个普通文本节点的末字**（域内的 `w:t` 因带 vertAlign 被跳过），
所以改前备份报 0 问题、改后才报 1 问题——**不是检查器不稳定，是域被搬坏了**。

### 四、重建参考文献表：模板必须在删除之前 deepcopy，锚点不能是"将被删的那一条"

两个都会**静默**失败（`prev.addnext()` 对已脱离文档树的节点不报错、只是什么也不做）：

1. `tpl_pPr = ref_paras[0].find(qn('pPr'))` 之后再 `remove` 原段落，用 `copy.deepcopy(tpl_pPr)`
   拷出来的是**空元素** → 新条目段落没有文字；
2. `anchor = paras[ref_idx[-1]]`（最后一条参考文献）随后被删 → 14 条新条目全部没进文档，
   而 `log` 照样打印「16 条 -> 14 条」。

处置：模板先 `copy.deepcopy` 再删；锚点取**首条参考文献的前一个段落**
（`first_ref.getprevious()` 向前找 `<w:p>`）。并在重建后立刻**重新数一遍落盘条目数**
（`^\[\d+\]` 开头的段落数），不等就 `SystemExit`——否则这类错误会一路走到交付。

#### 第一次修正后用户仍说"没改过来" —— 真正的根因是 **XML 结构非法**

第一轮我把插入点从"实词起始"改成"实词末尾"，文本顺序确实对了，但仍然是错的：
`insert_at.addprevious(sup)` 里 `insert_at` 是 **`<w:t>` 节点**，而 `<w:t>` 的父节点
**就是那个 `<w:r>`** —— 于是上标 `<w:r>` 被插进了正文 `<w:r>` **内部**：

```xml
<w:r><w:t>……必然选择</w:t><w:r><w:vertAlign w:val="superscript"/><w:t>[1]</w:t></w:r><w:t>。</w:t></w:r>
```

12 处全部如此。**这个错误能骗过当时所有验收**：

| 检查手段 | 结果 |
|---|---|
| lxml 解析 + 文本读取 | 正常，读到 `必然选择[1]。` |
| LibreOffice 渲染 / PDF 坐标 | **完全正确**（`[` x=127.5 < `。` x=135.6） |
| 我自写的"角标位置"校验 | PASS |
| **用户用 WPS 打开** | **报文件需修复，修复后角标跑到句号后面** |

LibreOffice 容忍非法结构并在内存里排好序，所以"渲染看着对"完全不能当交付依据。
**Word/WPS 会按 schema 修复，修复过程就把角标挪了位。**

**正确实现**（已固化进 `docxlib.insert_superscript_citation`）：把 run 在插入点处
**拆成两条 run**（两条各写一段文本，**不要搬 w:t 子节点**——搬节点会造成文本重复/错序：
实测读成 `。[1]前段文字结论句。前段文字结论句`），再把上标 run 插在两条 run **之间**，
使上标成为段落 `<w:p>` 的直属子元素。

**新增的两条硬校验（务必保留）**：

1. `r.getparent().tag` 必须是 `w:p`（或 `w:hyperlink`），**不能是 `w:r`**。
2. `check_nested_runs(root)`：`<w:r>` 内不得出现 `<w:r>`，计数必须为 0。
   一条命令的启发式：`len(root.iter(qn('r')))` 与 python-docx 的"段落直属 run 数"不一致 = 有嵌套。
3. 另写了 `validate_structure.py`（结构合法性 + 与基线比较段落子元素顺序），
   基线 PASS / 旧交付件 FAIL(12) / 新件 PASS 三点区分度已实测。

**另一个教训：交付目录里不能同时留旧版和新版。** 第一次修正后旧版文件被 WPS 占用删不掉，
于是 `_已修改(...).docx`（错的）和 `v2_角标在标点前(...).docx`（对的）并存，
用户打开的是旧的那个，反馈"你还是没改过来"。**交付前必须把旧版改名/删除或直接覆盖，
只留一个可辨认的成品名。**

- 规范：`……转向主动预防的必然选择` + 上标`[1]` + `。` → 「……必然选择[1]。」
- 不规范：`……转向主动预防的必然选择。` + 上标`[1]` → 「……必然选择。[1]」

**第一轮还有两个叠加的 bug（都已被上面 XML 结构问题掩盖，但同样要记）**：

1. 插入点算错：角标应插在**实词末尾**，第一轮却把插入点定成实词**起始字**，
   于是得到「必然[1]选择。」这种插在词中间的形式。
2. 自检假通过：收集角标时用 `p.findall(qn('r'))` 返回 0（当时上标 run 不在段落直接子层），
   退回 `p.iter(qn('r'))` 后又用 `D.get_text(p).find(marker)` 定位角标——`marker` 一旦取到
   空串，`find('')` **恒返回 0**，于是"后一个字符"永远取到段首字，自检恒真。
   同理 `list(p.iter(qn('t')))` 会把空 `w:t` 也计入位置，导致所有偏移错位。

**最终可用的判据（务必照抄）**：

```python
# 按文档顺序展平成 [('t', 文本) | ('sup', 角标文本)]，用下标 i 取前后字符
prev = ''.join(t for k, t in seq[:i] if k == 't')[-1:]
nxt  = next((t[0] for k, t in seq[i+1:] if k == 't' and t), '[')   # 角标算 '['
assert nxt in '。，；：！？、[]'          # 角标之后必须是标点（或同一句的下一个角标）
assert prev not in '。，；：！？、'      # 角标之前不能是标点
assert r.getparent().tag in (qn('p'), qn('hyperlink'))   # 结构必须合法！
```

只查"上标编号覆盖 1..N / 空文本上标数为 0"**发现不了**这个问题：本次那 12 个角标编号
完全正确、字体也正确、文本顺序也对，问题全在 XML 结构上。
判据与结构检查都已封装进 `docxlib.check_citation_placement()` / `check_nested_runs()`，
另加 `_task/学生P/validate_structure.py` 做"与基线比较"的整体结构校验。

### 发现并修复的 3 个缺陷（累计第 10–12 个）

10. **论文 docx 被当成意见文档**（最严重）：`审阅会计学…学生A初稿.docx` 文件名含"审阅"，

    "修改意见"**灌进语料。而且初稿还被 `backfill_docx` 与意见采集**各算一遍**。
    修法：新增 `docx_opinion_verdict()`——**带批注的 docx 一律判为论文**（归 backfill_docx，意见采集跳过）；
    无批注的按正文长度判定，并把 `MAX_BODY_AS_OPINION` 从 60000 收紧到 **8000** 字
    （宁可漏收一份超长意见文档，也不能收进一篇论文）。
11. **封面表格分段导致专业漏判**：国家开放大学模板把「专业」和值放在**不同段落**（同一表格的相邻单元格），
    只有"专业：X"同行形式的正则会静默漏掉。学生F的论文就是这样变成 `unknown` 的。
    修法：`major_from_cover()` 改为逐行扫描，支持三种排版——同行冒号、标签独占一行（取下一非空行）、
    复合标签「专业、层次：计算机科学与技术、本科」（按分隔符取第一段），并要求值**必须含中文**
    （挡掉正文里误命中的拼音，如阿则古丽文档里一度抓到的 `Gangwei`）。

### 五、目录（TOC 域）的缓存页码会把文本比对全搞乱

`check_toc.py` 原来直接 `get_text(p)` 取目录条目，拿到的是
`"1.1 课题研究背景1"` —— 因为一个目录段落里混着**两个域**：
HYPERLINK 域的显示文字是条目名，PAGEREF 域的显示文字是**已缓存的旧页码**。

两条修正（都已固化）：

- `split_toc_entry()` 用 `w:fldChar`/`w:instrText` 状态机剥掉 PAGEREF 域的显示文字；
- `norm()` 要**去掉所有数字串**：目录条目带 Word 生成的自动编号（"1.1 课题研究背景"），
  而正文标题的编号由 `numPr` 自动生成、**不落在 XML 文字里**（只有"课题研究背景"）。
  两边形态天然不同，不归一就永远对不上。

另外 `resolve_styles()` 原来只过滤名字含"字符"的样式，漏掉了英文名 `标题 2 Char`，
导致字符样式混进标题集合。要同时过滤 `char`。

### 六、目录是缓存，新增小节必然"暂时对不上"——用白名单表达，而不是放宽检查

本次新增了"1.6 研究内容与研究方法"和"5.3.2 性能测试"，但目录是 Word 域、

- `--expect-missing`：列出"预期目录里还没有"的标题；一旦它们出现在目录里就报 NOTE

- `--toc-only-ok`：列出"只在目录、正文没有"的合法条目（摘要/Abstract/目录/参考文献/致谢，

### 一、`docxlib` 只改已有部件，**新增部件必须自己写进包**（本次最费时的坑）

`save_docx()` 遍历的是**基线 zip 的条目**，只对 `replacements` 里命中已有条目的部件生效：
新键（`word/header2.xml`、`word/footer3.xml` …）**不会被写进 zip，也不报错**。
表现：只有原稿已有的 `header1/footer1/footer2` 被替换，新增的 header2/footer3/footer4
静默消失，而 `[Content_Types].xml` 里却已登记 → Word 会判文件需修复。
处置：`_task/学生A/build.py` 里用 `D.save_docx = save_docx_newparts` 覆盖，
在写完基线条目后再补写 `replacements` 里剩下的新部件。

### 二、`docxlib.qn()` 只接**裸标签名**，属性名要自己拼命名空间

`qn('w:p')` 返回 `{...}w:p`（**不是** `{...}p`），`el.set(qn('w:left'), '480')` 直接抛
`ValueError: Invalid attribute name`。写脚本时加两个本地包装：

```python
def _qn(tag):  return D.qn(tag[2:] if tag.startswith('w:') else tag)   # 元素名
def _attr(n):  return D.qn(n[2:]   if n.startswith('w:')   else n)    # 属性名
RID = '{http://schemas.openxmlformats.org/officeDocument/2006/relationships}id'
```

另：`docxlib` 没有导出 `_PPR_ORDER`（只有 `_RPR_ORDER`），pPr 子元素顺序需自带一份常量；
`enable_update_fields()` 返回的是 `(bytes, added)` **元组**，直接塞进 replacements 会写出元组。

### 三、目录（TOC）重建的三个要点

1. **域标记绝不能落在「目录」标题段里**。把 `fldChar(begin)/instrText(TOC)/separate`
   追加到标题段末尾，标题段就成了域的开头 —— Word 更新域时会把**标题本身一起替换掉**。
   必须新建一个独立段落承载域标记。
2. **TOC 条目里的 HYPERLINK 域会让 LibreOffice 丢条目文字**。实测条目名全部渲染不出来、
   只剩页码（「（一）研究背景与问题提出」消失）。去掉 HYPERLINK 域、条目名用普通文本，
   只保留 `PAGEREF 书签 \h` 出页码，渲染即正常。
3. 条目段落要套回模板自带的 **toc 1 / toc 2 样式号**（本例 13/15），否则 `check_toc.py`
   会报「目录条目 0」并把它当成目录为空。模板段落深度拷贝时**保留其 pStyle 即可**。

页数会因目录条目增多而 +1，**回填的实测页码必须重测一遍**（本次第一轮 25 页 → 第二轮 26 页，
正文首页由第 8 页变第 9 页，全部条目页码整体 +1）。
