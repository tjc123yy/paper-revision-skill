# 参考文献真实性核验方法

用户要求参考文献"真实可查"（如知网可查）时，禁止编造文献。逐条核验后再写入论文。

## 两条路线，先判断该走哪条

拿到一份现成的参考文献表时，先判断任务性质，再选路线——两条路线用的渠道不同：

| 情况 | 任务 | 路线 |
|---|---|---|
| 原表条目可能造假/字段残缺 | **只做核验**，不换文献 | 走下面「逐条核验渠道」，**不要动原表** |
| 要求"近5年""正式公开发表"，原表年份过老 | **整体替换** | 走「高效拿到含页码的新条目」+ 逐条核验 |

> 实战提醒（2026-09-30 学生C）：该生原 15 条文献**逐条核验全部 EXISTS-EXACT**
> （含 2 条报纸类），没有一条是编造的。但因为导师要求"近5年"，其中 2021 年的
> 13 条仍被替换。**核验通过 ≠ 满足时间要求**，两件事要分开报给用户。

## 逐条核验渠道（2026-09-30 实测有效，按命中率排序）

| 渠道 | 能否拿到完整字段 | 备注 |
|---|---|---|
| **期刊官网目次页**（如 `mpc.zsup.com.cn/?p=1123`） | ✅ 最好：给"作者（起始页）"，下一篇起始页 -1 即终止页 | 《现代计算机》这类自建站点最可靠 |
| `search.napstic.cn`（国家科技期刊平台） | ✅ 卷/期/页码齐全 | 比 `opaj.napstic.cn` 更稳 |
| `www.cqvip.com/search?k=<题名>` | ✅ 期刊条目给"年·期 起-止，共N页"；**学位论文也能确认** | 维普检索页比知网好抓 |
| 维普/万方**期刊目次页**（如 `cquc.net:8088/C/periodical/<刊>/<年-期>.aspx`） | ✅ 作者名单齐全 | 用来核对"等"字省略了几人 |
| `www.cnki.com.cn/Article/CJFDTotal-<码>.htm` | ⚠️ 有题名作者年期刊，**常缺页码** | 老式 cnki.com.cn 页比 wap 版稳定 |
| `wap.cnki.net/touch/web/Journal/Article/<码>.html` | ⚠️ 同上，且部分 404 | 可用但别当唯一来源 |
| `www.chndoi.org/Resolution/Handler?doi=<doi>` | ✅ 中国 DOI 注册记录给出题名+作者串 | 确认年/期用 |
| 报纸**原版电子版**（如 `szsb.sznews.com/PC/content/...`） | ✅ 逐字印证标题/副题/记者/日期/版次 | 报纸类文献的金标准 |
| `mall.cnki.net/magazine/Article/CCND/<码>.htm` | ✅ 报纸版次可由文献号末段推出（`…0830B170` → B17 版） | |
| **`coaa.istic.ac.cn/openjournal/periodicalArticle/<id>`** | ✅ 给页码，且列出相邻条目 | 可用相邻条目页差交叉验证 |

### 两个必须避开的坑

1. **页眉的"总第N期"不是页码**。《经济研究导刊》文章首页页眉印着"564"，
   实为总第564期；真实页码是 54-57（维普）。**子代理曾据此误判页码**，务必用维普/官网目次推翻。
2. **同一篇文献在不同 CNKI 接口可能给出不同页码**（本次《通化师范学院学报》一条：
   CNKI 引文记录 76-81，另一处目次接口 82-87）。**印刷页码无法独立复核时，
   如实标注"以知网导出引文为准，印刷页码未复核"**，不要默默二选一。

### 期刊卷号要与该刊自身序列自洽

不要凭"创刊年 + 年差"硬算卷号，要用同年其他期去反推。例如《电脑知识与技术》
2021=17、2025=21，则 2023=19 —— 与 `wap.cnki.net` 记录一致。
《无线互联科技》2023=20、2025=22、2026=23，同理自洽。

## 高效拿到「含页码」新条目的方法（2026-09-29 实战验证）

**逐条搜单篇效率低且常拿不到页码。最有效的办法是先找一篇同主题的新近正式论文，
抓它的参考文献表。** 同行评议论文里的著录条目字段完整，且可逐条回查。

| 渠道 | 能否拿到完整字段 |
|---|---|
| **`qkcb.jssti.cn/wxhlkj/...`（《无线互联科技》玛格泰克平台）** | ✅ **最好用**：页面「引用本文」给完整 GB/T 7714，含卷(期)与页码；页脚还有整篇参考文献表 |
| **`opaj.napstic.cn` / `search.napstic.cn`（国家科技期刊平台）** | ✅ 卷/期/页码齐全 |
| `www.xdxxkj.cn`（《现代信息科技》） | ✅ 页码齐全 |
| `www.hanspub.org`（汉斯出版社） | ✅「文章引用」行给年卷期页码；**参考文献表可直接抓**（一次拿一批） |
| `www.zgglkx.com`（《中国管理科学》） | ✅ `/CN/Y<年>/V<卷>/I<期>/<页>` 即完整信息 |
| `www.jryj.org.cn`（《金融研究》） | ✅ 同上（注意该刊用**总期号**，可写作 `2023, (11)`） |
| `www.jos.org.cn`（《软件学报》） | ✅「引用本文」区块齐全 |
| `api.crossref.org/works/<doi>` | ✅ 英文文献字段最全的单一来源 |
| `read.cnki.net/web/Journal/Article/<码>.html` | ⚠️ 只有 作者/刊名/年/期，**无页码**；部分文章 404 |
| `d.wanfangdata.com.cn/periodical/<码>` | ❌ JS 壳，抓不到引用字段 |
| `xueshu.baidu.com` | ❌ 403 反爬 |
| `mall.cnki.net` / `bianke.cnki.net` | ❌ 重定向或 404 |
| `api.crossref.org/works/<doi>`（CNKI 的 DOI） | ❌ CNKI 的 DOI 未在 Crossref 注册，返回 404 |

做法：用主题词搜到一篇近期论文 → 打开其 `qkcb.jssti.cn` 或 `hanspub.org` 门户页 →
抓「参考文献」区块，直接得到一批带页码的规范条目 → 再按本论文主题逐条筛选。

**拿不到页码时不要编。** 宁可留缺并明确告知用户"需从知网补全页码"，
也不能填一个看起来合理的假页码——那正是用户要修的毛病本身。

## 核验流程

1. **构造检索词**：每条候选文献用 `作者名 + 标题关键词` 搜索，例如：
   `黄玉平 论绩效考核在人力资源管理中的问题和对策`
2. **核对字段**：标题、作者、期刊名、年份、期号、页码与检索结果一致才采用；
   任何一项无法确认，就在交付说明里标注出来，**不要补全猜测值**。
3. **核对人数**：原文写"等"时要看实际作者数是否真的被省略。
   GB/T 7714 是"前三位作者，超出用等"——**只有 3 位作者就不能写"等"**。
4. **编号顺序**：GB/T 7714 顺序编码制要求**按正文首次引用顺序编号**，不是按主题分组。
   实操：先定好正文各处要引哪几篇，再按出现顺序编号，最后写文后列表。
   **强烈建议把"引用点 → 文献 key"写成数据，编号由 key 在列表中的位置推导**
   （见下方"编号不要手写"），不要手写数字。
5. **近5年要求**：用户要求"近5年"时，采用年份为当年往前推5年以内（如 2026 年任务用
   2021 年起）的文献，并显式核对每条年份。**任务做的哪一年，要写清楚**
   ——"2021 年算不算近5年"取决于任务年份，别自己拍。
6. **格式规范**：GB/T 7714 顺序编码制：
   - 期刊：作者.题名[J].刊名,年,卷(期):页码.
   - 学位论文：作者.题名[D].城市:学校,年.
   - 标准：发布机构.标准名称: 标准号[S].出版地:出版社,年.（无需页码）
   - 多作者：前三位作者，超出用"等"。
   - 作者超过一人时用逗号分隔。
7. **英文文献**：GB/T 7714 要求姓全大写、名缩写，如
   `JU Y, WANG Y, YANG J, et al. ... [J]. Journal Name, 2024, 19(3): 1869-1892.`
   Elsevier 类期刊无连续页码时用论文号（`59: 101247`）。

## 编号不要手写（2026-09-30 新增，踩过）

按首次出现顺序编号时**手写数字极易错位**——本次手写 `refs.py` 时把 [20]/[24]
等条目写错了位，改为"引用点 → key、编号由位置推导"后一次通过。

```python
ORDER = [k for k, _t, _y, _th in REFS]
NUM = {k: i + 1 for i, k in enumerate(ORDER)}   # 编号自动推导
CITE = {'bg1': 'fan2026', 'dom1_1': 'song2026', ...}   # 只写 key，不写数字
def number(point): return NUM[CITE[point]]
```

并让脚本自检：`正文引用编号集合 == set(range(1, N+1))`。
还要检查有无重复 key（`collections.Counter(ORDER)`）与未定义的 key。

## 检索注意事项

- 一条文献不确定时单独搜，不合并多个候选。
- 检索摘要与论文用词不一致时，优先采信能定位到期刊页面的结果。
- 找不到的文献立即替换，不保留存疑条目；替换后重新核验。
- 核验结果记录在交付说明中，标注每条文献的年份区间（证明近5年）**以及哪些字段未能确认**。
- **要产出一份带证据 URL 的核验清单**（如 `_task/<学生>/参考文献_候选N条_已核验.md`），
  逐条写明 `VERDICT / EVIDENCE / CORRECTIONS / NOTES`，并单列 `DROPPED` 说明每条被弃的原因
  （年份越界 / 页码不全 / 无法独立复核）。这份清单本身就是给用户和导师的交付物。

## 正文上标引用配套

- 正文引用处插入上标编号（见 docx-xml-patterns.md 第4节占位符方案）。
- 文后列表编号与上标一一对应，顺序一致。
- 上标数量应等于引用处数；验证时统计 superscript run 数量并核对编号集合覆盖 1 到 N 无缺失。
- **上标 run 的字体要单独设**（`rFonts/@eastAsia`），不能只靠继承。
  学校规范常明确要求"角标用宋体"（学生C批注⑤即如此）。
- 交付前用 `verify_revision.py --refs N --coverage N --sup-count M` 一次性核对。
